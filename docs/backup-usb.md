# USB สำรองข้อมูล (ต้องมีก่อนเปิดร้านจริง)

ฐานข้อมูลและ log ตาม พ.ร.บ.คอมพิวเตอร์ ม.26 อยู่บน SD card ของ Pi ซึ่งเสียได้เป็นเรื่องปกติ
ถ้ามีแต่ไฟล์สำรองบนการ์ดใบเดียวกัน การ์ดเสียเมื่อไหร่ ข้อมูลกับไฟล์สำรองหายพร้อมกัน
จึงต้องเสียบ **USB แฟลชไดรฟ์** ไว้กับ Pi ตลอด ระบบคัดลอกไฟล์สำรองรายวัน (ตี 3:30) ลง USB ให้เอง

## เตรียม USB (ครั้งเดียว)

ใช้ USB ขนาด 8 GB ขึ้นไป แล้ว **ตั้งชื่อ (label) ว่า `CAFEBACKUP`** ชื่อนี้ต้องตรงทุกตัวอักษร

**บน Windows** (ง่ายที่สุด): คลิกขวาที่ไดรฟ์ USB → Format → File system `exFAT` หรือ `FAT32`
→ Volume label `CAFEBACKUP` → Start (ข้อมูลเดิมใน USB จะหายหมด)

**บน Pi** (ถ้าถนัด): เสียบ USB แล้วดูชื่ออุปกรณ์ด้วย `lsblk` (เช่น `sda1`) แล้ว
`sudo mkfs.ext4 -L CAFEBACKUP /dev/sda1` — ระวังเลือกอุปกรณ์ผิด จะลบข้อมูลทิ้ง

## ใช้งาน

- เสียบ USB เข้า Pi ได้ทุกเมื่อ ไม่ต้องรีบูต ไม่เสียบก็บูตได้ตามปกติ
- ระบบเก็บไฟล์สำรองบน USB ไว้ 14 วันเท่ากับในเครื่อง (แต่ละไฟล์มีข้อมูลครบทั้งฐาน รวม log ย้อนหลังทั้งช่วงเก็บ)
- ดูผลได้ที่หน้า **สถานะระบบ → สำรองข้อมูล**: "✓ คัดลอกลง USB แล้ว" หรือ "⚠ ไม่ได้คัดลอกลง USB"
- ถ้าไม่ได้เสียบ ระบบจะไม่เขียนลง SD card แทนแบบเงียบ ๆ (กันเข้าใจผิดว่ามีสำเนานอกเครื่อง)

## กู้คืนเมื่อ SD card เสีย

1. ติดตั้งระบบใหม่บนการ์ดใหม่ด้วย `install.sh` และ **นำ `/etc/cafe-wifi/secrets.env` ตัวเดิมกลับมาวาง** —
   ไฟล์สำรองมีเลขบัตรที่เข้ารหัสไว้ ต้องใช้กุญแจในไฟล์นี้ถอด (ควรเก็บสำเนา secrets.env ไว้ที่ปลอดภัยแยกต่างหาก
   **ห้ามเก็บไว้ใน USB อันเดียวกับไฟล์สำรอง**)
2. `sudo mysql cafewifi < sql/001_schema.sql` (และ migration อื่นใน `sql/` ตามลำดับ)
3. `gunzip -c /mnt/cafebackup/cafe-wifi/cafewifi-<วันล่าสุด>.sql.gz | sudo mysql cafewifi`

ทดสอบแล้วบน Pi จริง (3 ต.ค. 2026) ด้วย USB จำลองแบบ FAT: ไม่เสียบ → เตือน ไม่เขียนลง SD ·
เสียบ → mount เองและคัดลอกสำเร็จ (gzip ถูกต้อง) · ถอด → เตือนอีกครั้ง
